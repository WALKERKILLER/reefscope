# 无权重时如何验证工程基础

新成员还没有授权视频和权重时，可以先验证仓库是否具备可协作的规则与契约。运行 `python3 scripts/check.py`，失败会停止并返回非零退出码。

## Step 1: 从同一清单选择检查

入口先调用 repo-seed 的 manifest 驱动 runner，检查治理文件、MADR/spec/复盘、链接和 placeholder；再执行项目公开边界、VibeWise 分发完整性、模拟数据和反例测试。本地与 CI 共用入口，避免两套检查逐渐分离。

## Step 2: 拒绝不应公开的文件

检查器枚举 Git 可见文件，包括未忽略的新文件。若误将 `.pt` 权重或 `.env` 强制加入暂存区，检查应失败。忽略文件不会被扫描，因此发布前仍需人工复核暂存区；此检查不能证明没有任何隐私泄漏。

## Step 3: 检查示例之间的科研约束

原调研中的标准库脚本核对 Run ID、轨迹坐标、时间单调性、热图质量守恒、taxonomy 和缺失指标语义。它读取示例 JSON/JSONL，不训练模型，也不接受任意用户输入作为已验证数据。

## Step 4: 将基础通过与功能通过分开

看到 PASS 只能证明此次执行覆盖的静态与模拟约束。后端测试和前端构建由 CI 的独立 job 执行。真实视频、人工真值、GPU 与浏览器交互验收由相关工作包交付。

验证入口是根目录的 `python3 scripts/check.py`。相关实现定位见 [代码地图](../code-map.md)。
