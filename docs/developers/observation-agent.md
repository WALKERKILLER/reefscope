# 观测分析 Agent

本文是参考说明，契约见 [观测分析 Agent spec](../specs/draft-observation-agent.md)，取舍见 [0007](../adr/0007-observation-agent-loop.md)。Agent 与报告解读共用顶栏齿轮中的“模型服务”配置（见 [观测报告](observation-reports.md)），服务需要支持工具调用。

## 运行

Agent 循环不在 Web 进程中执行，需要另开一个进程，环境与 `runserver` 相同：

```bash
cd backend
python manage.py run_agent_worker        # 持续领取；--once 只处理一个 Run
```

没有运行 Worker 时任务保持“排队中”，界面在 15 秒后提示。Worker 重启后，租约过期的运行中 Run 记为失败；等待批准的 Run 不受影响。

## 管线

```
用户目标 → [模型] 计划 update_plan
         → [模型] 选择工具 ──读取类──→ 平台执行 → 结果登记到证据台账 → 回到模型
                         └─行动类──→ 提议 → 暂停等待批准 ─批准/拒绝→ 结果回到模型
         → [模型] 回答 → 平台审计 ─未通过（≤ 2 次）→ 退回改写
                                └─通过或用尽→ 回答（未核对数字高亮）
```

每轮模型调用前续租并检查“停止”。步骤（计划、工具、说明、审计、批准、继续、回答、错误）按序号写入 `AgentStep`，界面每秒取增量。

## 工具

| 工具 | 类型 | 作用 | 登记的证据 |
| --- | --- | --- | --- |
| `update_plan` | 读取 | 写入 1–8 步计划，界面侧栏显示 | — |
| `get_playback_context` | 读取 | 大屏会话的当前时刻、当前帧可见鱼数、全片平均、最近的珊瑚采样帧 | `P{n}.*` |
| `get_site_overview` | 读取 | 水深、备注、最近 10 份报告的关键指标 | `SITE.depth`、`H{日期}.*` |
| `list_videos` | 读取 | 视频与各 Run 的状态、模型、机位；缺少的分析 | `V{视频}.label` |
| `compute_observation_metrics` | 读取 | 与报告相同的确定性指标、比较、局限 | `S{n}.*` |
| `fish_activity_timeline` | 读取 | 按时段的平均可见鱼数，最活跃与最安静时段 | `T{n}.*` |
| `fish_window_summary` | 读取 | 指定时间窗的平均数、峰值、有鱼帧比例、追踪 ID | `W{n}.*` |
| `coral_frame_review` | 读取 | 白化比例最高、珊瑚占比最高/最低的采样帧与时间 | `C{n}.*` |
| `model_evidence` | 读取 | 模型类别、训练报告与独立评估数量 | — |
| `crw_alert_level` | 读取 | 按 CRW v3.1 从 HotSpot 与 DHW 计算等级 | `E{n}.*` |
| `search_references` | 读取 | 检索 `sources.py` 资料卡 | — |
| `propose_analysis_run` | 行动 | 用最新注册模型与默认参数排队一次分析 | — |
| `propose_observation_report` | 行动 | 用一个指标集起草报告；先审计，未通过退回 | — |

工具描述与参数 schema 在 `backend/app/agent/tools.py` 的 `TOOLS` 中，同一份定义按两种格式发送。工具结果的数值以“显示值 · 标签”给模型，不给原始浮点数，以免模型自行换算。

## 监测大屏

观测员在“监测大屏”点顶栏的“观测助手”（快捷键 A），或在右栏切到“观测助手”，助手会停靠在右栏，视频照常播放。

- 会话属于当前视频（`/api/v1/tasks/{id}/agent-sessions`）。每条消息都会附带播放时刻和该视频已完成的鱼类、珊瑚 Run。
- 回答中带时间的数值（`T{n}` 时段、`W{n}` 时间窗、`C{n}` 采样帧时间、`P{n}.time`）显示为 ▶ 按钮，点击跳到视频该时刻。只有指向当前视频的时间可以点击。
- 未归档的会话可以分析，但不能读取观测点历史或起草报告；在面板顶部选择观测点即可归档（`PATCH /api/v1/agent-sessions/{id}`）。
- 输入框沿用 `.input` 的颜色与焦点环：外框 `radius-lg`、内边距 4 px，内部按钮 `radius`，圆角同心。文本框随内容增高，有上限，不显示拖拽手柄。

## 审计与数值

回答与草稿中的数值只能写 `{{ID}}`；平台替换为显示值。以下情况算未通过：

- 未知 ID。
- 未知资料 ID。
- 没用占位符的阿拉伯数字。

退回时把具体 ID 和数字告诉模型。用尽 2 次后，回答照常显示，问题处标黄。

报告草稿只能用一个指标集（如 `S1`）内的 ID。保存时去掉前缀，再按所选 Run 重建事实，所以报告与手动生成的报告结构一致，章节名为“Agent 解读”。时间线和采样帧复核的数值只在会话中可见。

## 批准

批准卡片显示草稿全文（数值已替换）或待排队的视频与模型。可附备注；拒绝时备注作为工具结果交给模型。

- 批准保存的报告记录 `agent.mode = "agent_run"` 与 `agent_run_id`，在报告记录中显示为“Agent 起草”。
- 批准排队的分析由分析 Worker 处理，本次会话内不会完成。

## 预算与失败

| 限制 | 值 | 超出时 |
| --- | --- | --- |
| 模型轮次 | 14 | 要求收尾；仍调用工具则失败 `agent_budget_exhausted` |
| 工具调用 | 24 | 同上 |
| 每段执行时长 | 300 s（批准后继续时重新计时） | 同上 |
| 审计退回 | 2 | 接受并标记 |
| 单个工具结果 | 8000 字 | 截断并提示缩小范围 |

模型服务错误沿用 [观测报告](observation-reports.md) 的错误码。输出被截断时为 `agent_output_truncated`。

## 外发内容

外发给模型的内容：

- 系统提示（观测点名称、日期、资料卡 ID）。
- 对话记录与工具结果。

不发送坐标、文件名、画面和 Key；视频以“视频 #N”指代，文件名只在界面显示。Run ID 会出现在工具结果中，供模型选择 Run。

## 与同类平台的对照

| 平台 | 做法 | 本模块对应 |
| --- | --- | --- |
| Snowflake Cortex Agents | 规划、工具、反思、预算、轨迹 | 计划工具、步骤轨迹、预算 |
| Databricks Genie Agent 模式 | 研究计划、多次查询、带引用的报告 | 多工具取证、资料卡引用 |
| Palantir AIP | 提议待审、决策日志 | `propose_*` 与批准卡片、步骤记录 |
| Microsoft Fabric 数据 Agent | 展示中间步骤与查询 | 可展开的工具参数与返回指标 |
| ReefCloud（AIMS） | 影像自动分析与标准化报告 | 报告沿用确定性模板 |

来源见 [0007](../adr/0007-observation-agent-loop.md)。

## 验证边界

`backend/app/test_agent.py` 用本地脚本化模型服务覆盖两种格式的循环、审计退回、批准与拒绝、跟进、预算、停止和工具错误。测试不调用真实模型，不证明任何模型的规划质量；新接入的服务应先在“测试连接”后用一个简单任务确认它会调用工具。
